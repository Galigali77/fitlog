## 1. 引言

### 1.1 编写目的

本文档描述一款**健身记录网页**的完整软件需求，供产品、设计与开发人员作为设计、实现和验收的依据，也作为后续迭代的基线文档。

### 1.2 产品背景与定位

市面上的健身类 App（如训记、Hevy、Strong）普遍存在以下问题：

- 功能日益臃肿：社区、直播课、商城与「记录」这一核心诉求混杂；
- 核心功能付费墙：渐进超负荷建议、数据分析等基础能力被做成订阅制；
- 强制注册与云端绑定：数据存储在他人的服务器上，存在隐私与迁移成本。

本产品的定位：

> **「记得快、看得懂、会提醒你加片」——本地优先、无账号、复盘驱动、纯手机网页的健身记录工具。**

差异化三条主线：

1. **零门槛**：打开网页即用，不注册、不登录、可离线；
2. **数据主权**：所有数据保存在用户浏览器本地，可一键导出/迁移；
3. **复盘建议**：不止展示图表，还基于规则给出「下次加多少重量」的建议，免费替代私教的记录职能。

### 1.3 范围

**包含**：动作浏览与检索、训练过程记录、训练计划管理、训练数据统计与可视化复盘、数据导入导出。

**不包含**（明确边界，见第 9 节）：社区/社交、在线课程/视频内容、电商、营养与饮食记录、与健康平台（Apple Health 等）的深度集成。

### 1.4 术语与参考资料

| 术语 | 说明 |
| --- | --- |
| 动作（Exercise） | 一次训练中的基本单元，如「杠铃深蹲」 |
| 组（Set） | 一个动作的连续重复，记录字段：重量、次数、RPE（可选） |
| 训练（Workout） | 一次完整的训练会话，包含多个动作、每组数据与时间 |
| 计划（Routine/Plan） | 预先编排的一组动作模板，可绑定到星期或按轮换执行 |
| 渐进超负荷（Progressive Overload） | 随能力增长逐步增加训练负荷的原则 |
| e1RM | 估算单次最大重量（Epley 公式：重量 × (1 + 次数/30)） |
| PR | 个人纪录（Personal Record） |
| RPE | 自感用力系数（Rate of Perceived Exertion，6–10） |
| PWA | Progressive Web App，可安装到主屏幕、离线运行的网页应用 |
| IndexedDB | 浏览器端结构化本地数据库 |

参考资料：

- openGym 开源项目（动作数据来源）：https://github.com/DuarteSantos8/openGym
- openGym 动作库数据目录：`catalogue/`（动作名称、肌群、器械、文字要领）
- 《软件需求规格说明书》通行范式（IEEE 830 / GB/T 9385）

## 2. 用户分析

### 2.1 目标用户

| 用户类型 | 特征 | 核心诉求 |
| --- | --- | --- |
| 健身新手（主） | 大学生、初入健身房，不懂系统训练 | 告诉我今天练什么；帮我记住上次举了多重 |
| 健身爱好者（主） | 有 6 个月以上训练经历，自己带计划 | 记录要快；让我看到有没有进步 |
| 居家/宿舍训练者（次） | 器械有限（哑铃/徒手） | 动作库能按器械过滤；给替代动作 |
| 隐私敏感用户（次） | 反感注册和云同步 | 数据留在本地，能导出走人 |

### 2.2 典型使用场景

- **场景 A（记录）**：用户在健身房组间休息 90 秒，掏出手机打开网页 → 自动进入今天的训练 → 上一组数据已预填 → 点一下完成记录，计时器开始 90 秒倒计时。
- **场景 B（复盘）**：周日晚上用户打开「复盘」页 → 看到本周 4 次训练的热力图、上一次身材记录的正面/背面照片对比、以及系统提示「平板卧推已连续两次达到次数上限，建议下次 50kg → 52.5kg」；若距离上次身材记录已满 15 天，顶部出现「今天该记录身材了」的高亮提醒。
- **场景 C（开练）**：新手选择「宿舍哑铃计划」→ 系统给出 A/B 轮换的训练 → 每个动作有文字要领 → 按顺序练完，自动标记完成。

### 2.3 用户角色

本产品不设账号体系，无后台角色。唯一的「管理端」是动作数据的初始化与版本更新（由开发者维护，随应用分发）。

## 3. 功能需求

优先级标记：**P0** = MVP 必须有；**P1** = 第一个正式版本应有；**P2** = 锦上添花，可排期。

### 3.1 模块一：动作库（FR-EX）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-EX-01 | 提供不少于 3000 个动作条目（取自 openGym `catalogue/` 动作数据），**含动作 GIF 演示动图**，构建期本地打包分发，不依赖网络 | P0 |
| FR-EX-02 | 动作条目字段：名称（中英）、目标肌群、协同肌群、所需器械、动作类型（力量/有氧/拉伸）、文字要领、难度、GIF 动图 | P0 |
| FR-EX-03 | 支持按名称模糊搜索、按肌群筛选、按器械筛选，三者可组合 | P0 |
| FR-EX-04 | 提供身体地图（正面/背面人体示意图），点击肌群直接列出对应动作 | P1 |
| FR-EX-05 | 支持「居家/宿舍模式」快捷过滤：一键只显示徒手 + 哑铃动作 | P1 |
| FR-EX-06 | 用户可新建自定义动作（名称、肌群、备注），可编辑、可删除 | P1 |
| FR-EX-07 | 动作详情页展示文字要领、肌群信息与 **openGym 自带的 GIF 演示动图**（播放、可暂停）；无动图的动作用文字要领兜底展示 | P0 |
| FR-EX-08 | 提供「同肌群替代动作」推荐：记录过程中某动作缺器械时，一键列出同目标肌群的其他动作 | P1 |

### 3.2 模块二：训练记录（FR-LOG）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-LOG-01 | 一次训练包含：日期时间、动作列表；每个动作包含若干组，每组字段为重量（kg，可空=自重）、次数（或秒数）、RPE（可选） | P0 |
| FR-LOG-02 | 组数据支持增删改；删除可撤销 | P0 |
| FR-LOG-03 | 开始记录时，若该动作存在历史数据，自动预填上次的重量与次数，用户仅需修改变化项 | P0 |
| FR-LOG-04 | 每组记录完成后可启动组间休息计时器（默认 90s，可自定义 15s–15min），到时震动 + 闪屏提醒 | P0 |
| FR-LOG-05 | 自动 PR 检测：当某动作的重量或单次容量超过历史最佳时，当场弹出「新纪录」提示 | P0 |
| FR-LOG-06 | 计时类动作（如平板支撑）：记录秒数而非次数 | P1 |
| FR-LOG-07 | 单侧动作（如箭步蹲）：支持每侧分别记次数 | P2 |
| FR-LOG-08 | 训练可关联到某个计划（标明「按计划完成」），也可作为自由训练 | P0 |
| FR-LOG-09 | 支持事后补记与修改历史训练（改日期、改数据），修改后相关统计自动重算 | P1 |
| FR-LOG-10 | 训练过程中的屏幕常亮选项（开关） | P1 |

**核心体验指标**：从打开网页到记录完一组，不超过 3 次点击、3 秒（在数据已预填的前提下）。

### 3.3 模块三：训练计划（FR-PLAN）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-PLAN-01 | 系统内置 4 套经典计划模板：5×5 全身、Push/Pull/Legs、三分化（胸肩三头/背二头/腿）、宿舍哑铃版 | P0 |
| FR-PLAN-02 | 用户可基于任意模板创建自己的计划，或从零新建；计划由若干动作及其目标组数×次数构成 | P0 |
| FR-PLAN-03 | 计划编排支持两种模式：①绑定星期（周一练胸、周二练背……）；②轮换模式（A/B/C 按完成顺序依次推进，不限星期） | P0 |
| FR-PLAN-04 | 「今天练什么」入口：根据计划模式直接给出今日/下次应练内容，一键开始记录 | P0 |
| FR-PLAN-05 | 计划可整体导出为文件/链接，他人导入即可使用（轻分享，不做社区） | P1 |
| FR-PLAN-06 | 计划完成度统计：按计划应练次数 vs 实际完成次数 | P1 |
| FR-PLAN-07 | 计划内的渐进超负荷参数可配置：次数上限、加重幅度（默认 +2.5kg） | P1 |

### 3.4 模块四：复盘分析（FR-ANA）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-ANA-01 | 训练热力图：以日历/年视图展示每日训练情况（GitHub 风格格子），按训练容量映射颜色深浅 | P0 |
| FR-ANA-02 | 身材记录：用户每 15 天拍摄一组身材展示照片，每次**至少包含正面与背面两张**；支持拍照/相册上传、历史记录时间线浏览（按日期倒序）、下次记录倒计时提醒（到期高亮提醒）；照片仅存储于本地浏览器，不上传任何服务器 | P0 |
| FR-ANA-03 | 渐进超负荷建议引擎：当某动作连续 N 次（默认 2）训练达到目标次数上限时，生成「建议加重 +X kg」提示；达到次数下限以下时，提示维持或减重 | P0 |
| FR-ANA-04 | 肌肉群覆盖热力图：将历史训练量映射到身体地图上，标识「高频肌群 / 低频肌群 / N 天未训练肌群」 | P1 |
| FR-ANA-05 | 每周自动复盘（每周日晚生成）：训练次数、总容量、主要动作重量变化、计划完成度，以文字摘要 + 关键图表呈现 | P1 |
| FR-ANA-06 | 训练详情与时间线：倒序列表展示历史训练（日期、主要肌群、动作数、总容量），可点入查看明细 | P0 |
| FR-ANA-07 | 分析结果可导出（见模块五） | P0 |

### 3.5 模块五：数据管理（FR-DATA）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-DATA-01 | 所有用户数据（训练记录、计划、自定义动作、设置）存储于浏览器本地 IndexedDB，无服务端持久化 | P0 |
| FR-DATA-02 | 导出完整数据为 JSON 文件（备份与迁移） | P0 |
| FR-DATA-03 | 从 JSON 导入恢复数据（全量覆盖式恢复） | P0 |
| FR-DATA-04 | 导出 CSV：训练明细表（日期、动作、组数、重量、次数），供 Excel 分析 | P0 |
| FR-DATA-05 | 生成分享卡片图片（PNG）：单次训练摘要或进步数据卡片，便于社交平台分享 | P1 |
| FR-DATA-06 | PWA 离线可用：首次加载后断网仍可完整使用全部功能（动作库已本地打包） | P0 |
| FR-DATA-07 | 可安装到主屏幕（Add to Home Screen），全屏运行、无浏览器地址栏 | P1 |
| FR-DATA-08 | 支持导入 FitNotes / Strong 的 CSV（P2，仅在用户提出迁移需求时实现） | P2 |

### 3.6 主要用例

**用例 1：完成一次训练**
参与者：用户。前置：已选择或存在今日计划。
流程：打开网页 → 进入「今日训练」→ 系统给出今日动作清单 → 用户完成第一组并记录（数据预填）→ PR 检测提示（如有）→ 休息计时器自动启动 → 重复直至全部动作完成 → 用户结束训练 → 系统展示本次摘要（时长、总容量、PR 数）→ 数据落盘。

**用例 2：查看本周复盘**
参与者：用户。前置：本周有 ≥1 条训练记录。
流程：打开「复盘」→ 查看热力图 → 在「身材记录」区上传正面与背面照片（或查看历史记录时间线）→ 阅读渐进超负荷建议（如「卧推建议 +2.5kg」）→ 可导出分享卡片。

**用例 3：制定自定义计划**
流程：进入计划页 → 从模板复制或新建 → 添加动作（从动作库搜索）→ 设置每组目标次数与组数 → 选择星期绑定或轮换模式 → 保存 → 在「今天练什么」中生效。

## 4. 数据需求

### 4.1 核心数据实体

| 实体 | 关键字段 | 说明 |
| --- | --- | --- |
| Exercise（动作） | id、名称(zh/en)、主肌群、协同肌群、器械、类型、要领、是否自定义 | 系统动作随应用打包；自定义动作存本地 |
| Workout（训练） | id、开始/结束时间、关联计划ID（可空）、备注 | 一次训练会话 |
| WorkoutExercise（训练动作） | id、workoutID、exerciseID、顺序 | 训练与动作的关联 |
| Set（组） | id、workoutExerciseID、重量、次数、RPE、类型（正式/热身） | 最小记录单元 |
| Routine（计划） | id、名称、模式（星期/轮换）、当前轮换位置 | 计划本体 |
| RoutineItem（计划项） | id、routineID、exerciseID、目标组数、目标次数区间、加重幅度 | 计划内动作 |
| BodyWeight（体重，可选） | 日期、数值 | 用于体重记录（P2 可做可不做） |
| BodyPhoto（身材记录） | id、日期、正面照片、背面照片（可扩展侧面） | 每 15 天一组；照片仅存本地 |

### 4.2 数据关系

一个 Workout 包含多个 WorkoutExercise，一个 WorkoutExercise 包含多个 Set（1:N:N）；Routine 与 RoutineItem 为 1:N；Exercise 被 WorkoutExercise 与 RoutineItem 引用。

### 4.3 数据量估算

单用户：每训练约 8 动作 × 4 组 ≈ 32 条 Set 记录；一年 200 次训练 ≈ 6400 条 Set + 1600 条 WorkoutExercise + 200 条 Workout，总计 < 1 MB 文本数据，IndexedDB 完全无压力。

## 5. 界面与交互需求

### 5.1 设计原则

- **移动端优先**：全部界面按 375px 宽度设计，桌面端仅为自适应放大，不单独做桌面版；
- **单手可达**：主要操作按钮位于屏幕下半部；
- **少即是多**：主界面 4 个入口以内，不做底部 5 个 Tab 以上的结构。

### 5.2 页面清单

| 页面 | 核心内容 | 对应模块 |
| --- | --- | --- |
| 今日页 | 「今天练什么」卡片 + 快速开始 + 最近训练摘要 | 记录/计划 |
| 记录页 | 当前训练的动作列表、逐组记录、休息计时器悬浮条 | 记录 |
| 时间线页 | 历史训练倒序列表、详情查看与编辑 | 记录/复盘 |
| 复盘页 | 热力图、身材记录（15 天周期拍照）、肌肉地图、超负荷建议、周报 | 复盘 |
| 动作库页 | 顶部搜索、左侧肌群竖栏、器械筛选、GIF 双列卡片、动作详情 | 动作库 |
| 计划页 | 我的计划、模板市场、计划编辑 | 计划 |
| 设置页 | 计时器默认值、单位、数据导入导出、关于 | 数据 |

### 5.3 关键交互要求

- 逐组记录采用「点按 +」的大按钮交互，避免键盘输入为主；
- 所有删除操作支持撤销（Snackbar）；
- 计时器在页面切换后仍继续（Web Worker 或 Service Worker 保活），回到页面可见剩余时间。

## 6. 非功能需求

| 类别 | 需求 |
| --- | --- |
| 性能 | 首屏加载（4G）≤ 3s；动作库搜索响应 ≤ 200ms（本地索引）；逐组记录操作 ≤ 100ms 反馈 |
| 兼容性 | 支持 iOS Safari 15+、Android Chrome 90+；PWA 在两大平台可安装 |
| 可用性 | 核心记录流程不依赖网络；断网状态有明确提示但不阻塞使用 |
| 可靠性 | 训练记录写入采用事务式落盘，异常中断（关标签页）不丢已记录的组 |
| 隐私与安全 | 无账号、无服务端、无遥测；不采集任何个人信息；数据不出设备（除非用户主动导出/分享） |
| 可维护性 | 前端工程化（组件化 + 类型检查）；训练数据模型版本化，预留迁移机制 |
| 可访问性 | 主要功能可仅用触摸完成；关键图表提供文字替代摘要 |

## 10. 验收标准（摘要）

1. 在 iOS Safari 与 Android Chrome 上，断网状态下可完成：浏览动作库 → 开始训练 → 记录 3 个动作各 3 组 → 查看热力图，全程无报错、无数据丢失；
2. 预填功能：对已有历史数据的动作，开始记录时自动带出上次重量与次数；
3. 超负荷建议引擎：按测试用例输入「连续两次达到次数上限」数据，系统给出正确加重建议；
4. 数据可完整导出 JSON 并在清空浏览器数据后恢复；
5. 逐组记录流程经可用性测试，平均操作 ≤ 3 次点击/组。
